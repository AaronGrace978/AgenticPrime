AgenticPrime User Guide

Five agents argue. The app appears.

AgenticPrime is an intent-to-interface runtime. It shows five visible agent personas assembling a temporary task surface from one plain-English intent. It is best used as a local experiment, prototype shell, or model provider test bench.

What is real vs simulated?

Real: the React UI, animation, use-case selection, local Vite provider route, provider calls, and JSON normalization. Simulated: capability cards, tool receipts, approvals, submissions, pings, and any external side effect unless you wire a real backend tool behind it.

Basic flow

  1. Run launch.bat or npm run dev.
  2. Pick a use case card from the shelf.
  3. Write one clear mission in the intent box, or use the default.
  4. Choose Offline demo for the reliable path, or configure a live provider.
  5. Click Generate surface.
  6. Use the time scrubber to replay how the surface appeared.
  7. Approve the simulated execution to see the receipt ending.

Good intent prompts

Keep it short and situational. You are telling the swarm what job this temporary UI should perform.

  • I am at AI Tinkerers Boston. Help me prep a 5-minute pitch that wins the room.
  • I have 12% battery and an outage. Show the next three actions and the one risk I need to approve.
  • Build a decision surface for whether I should quit my job and found a company this month.

Ollama setup

Ollama local daemon: install Ollama, run ollama serve, and pull a model. For cloud-backed local models, run ollama signin, then pick one of the dropdown models such as kimi-k2.6:cloud, deepseek-v4-pro:cloud, or gpt-oss:120b-cloud. Pull it first if needed. Use endpoint http://localhost:11434 and leave the API key blank.

Ollama Cloud API: create an API key at https://ollama.com/settings/keys. Use the app's Ollama Cloud API provider and choose from the dropdown catalog: kimi-k2.6, deepseek-v4-pro, glm-5.1, qwen3-coder-next, and others. Direct Cloud API calls use https://ollama.com/api/chat under the hood.

Production note

This repo is safe for local BYOK demos. A public deployment should move provider calls and API keys behind a real backend secret boundary before allowing untrusted users.
